# Contributing to OpenFlow

Thank you for contributing to OpenFlow.

OpenFlow is an open-source developer learning platform, and contributions are welcome across frontend development, backend development, algorithms, visualization, AI, analytics, testing, DevOps, accessibility, performance, and documentation.

## Before You Start

Before working on an issue:

1. Read the issue completely.
2. Check whether someone is already working on it.
3. Comment on the issue expressing your interest.
4. Wait for the issue to be assigned to you.
5. Discuss major architectural changes before implementation.

## Getting Started

### 1. Fork the Repository

Fork the OpenFlow repository to your GitHub account.

### 2. Clone Your Fork

```bash
git clone https://github.com/ali0786mehdi/OpenFlow.git
cd OpenFlow
```

### 3. Create a Branch

Create a separate branch for your contribution.

```bash
git checkout -b feature/your-feature-name
```

Use descriptive branch names:

```text
feature/feature-name
fix/bug-name
docs/documentation-name
refactor/component-name
test/test-name
```

### 4. Make Your Changes

Keep your changes focused on the assigned issue.

Avoid unrelated modifications.

### 5. Test Your Changes

Before opening a pull request, make sure:

- The project builds successfully.
- Existing tests pass.
- Your changes do not introduce unnecessary warnings or errors.
- New functionality has appropriate tests where applicable.

### 6. Commit Your Changes

Use clear commit messages.

Examples:

```text
feat: add binary search visualization
fix: correct algorithm step calculation
docs: improve contribution guide
test: add sorting algorithm tests
refactor: simplify visualization engine
```

### 7. Open a Pull Request

Push your branch:

```bash
git push origin feature/your-feature-name
```

Then open a Pull Request against the `main` branch.

## Pull Request Guidelines

A good pull request should:

- Explain what was changed.
- Reference the relevant issue.
- Include appropriate tests.
- Keep the scope focused.
- Follow the existing project structure.
- Update documentation when necessary.

Use the PR template when submitting your contribution.

## Issue Guidelines

Before opening an issue:

- Search existing issues.
- Make sure the issue has not already been reported.
- Provide enough information for another contributor to understand the problem.

For feature requests, clearly explain the problem and proposed solution.

Contributions should prioritize:

- Readability
- Maintainability
- Type safety
- Reusability
- Performance
- Accessibility
- Testability

Avoid unnecessary complexity.

## Questions

If you are unsure about an implementation, open a discussion or comment on the relevant issue before beginning major work.
